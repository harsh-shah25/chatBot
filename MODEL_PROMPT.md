# Exact model prompt — with and without web search

Generated by calling the real code (`system_prompt()` in `chatbot/core.py` and
`HostedProvider.open_stream()` in `chatbot/providers.py`) and capturing the HTTP body
instead of sending it. Provider is the one in `.env`: **gemini / gemini-3.1-flash-lite**.

The student, chat history, and Tavily results are **made-up sample data**. Everything else
(rules text, labels, ordering, JSON layout, generation config) is exactly what the server sends.

## How the path is chosen (`ChatService.prepare`, `chatbot/server.py`)

1. The student context is loaded (from the Redis snapshot, or careerAPI on the first message)
   and filtered through `normalize_context()`. Only whitelisted fields get through (first name,
   current career, profile, quiz assessment, last 3 attempted contests). Email, surname and raw quiz answers are dropped.
2. `needs_search(message)` checks **only the current message** against:
   `\b(latest|current|today|this year|20(?:2[4-9]|3\d)|deadline|date)\b` (case-insensitive).
3. **No match → Path A** (no web search).
4. **Match → Tavily search.** The query is the message with emails/phones redacted (500 chars max).
   Request settings: `basic` depth, max 5 results, country `india`, no raw content.
   - Results found → **Path B**. Each snippet is cut to 1,800 chars.
   - Search errors **or returns 0 usable results** → **the model is not called.** The user gets this fixed reply:
     *"I couldn't verify current information right now. Please check an official college, exam, or government source and try again later."*
5. History (up to 6 exchanges, sent by the client) goes in as normal chat turns. The current message is the last user turn.

Endpoint (both paths): `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:streamGenerateContent?alt=sse`

Generation config (both paths): `temperature 0.3`, `maxOutputTokens 1200`.

## Notes / things worth knowing

- **Path B is Path A plus one block.** The only difference is the `Web evidence ...` section added at the end of
  the system instruction. The rules text is identical in both paths.
- **The published date of a result is not sent to the model.** `TavilySearch` collects `date`, but
  `system_prompt()` only writes title, URL and snippet. The date only goes to the UI `sources` list.
- **`search_failed=True` is never used.** `system_prompt()` has a branch that says "Current information could not
  be verified...", but `prepare()` never passes `search_failed`. A failed search returns the fixed reply instead.
- **Search ignores history.** A follow-up like "what about its deadline?" sends only that text to Tavily,
  without the earlier topic. Results may be poor.
- **Groq / OmniRoute** get the same system text, sent as `{"role": "system", "content": ...}`, followed by the
  history and the user message. The body uses `"model"`, `"stream": true`, `"temperature": 0.3`, `"max_tokens": 1200`.
- `Current date:` is the server's UTC date when the request is made.
